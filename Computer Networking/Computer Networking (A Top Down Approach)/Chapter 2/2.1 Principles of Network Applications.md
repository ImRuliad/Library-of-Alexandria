*The core of network application development is writing programs that run on different end systems and communicate with each other over the network*

- This does not require you to write software that runs on network-core devices (routers & switches)
- Network-core devices do not function at the application layer but at the network layer and below.

## ***2.1.1 Network Application Architectures***
---
*Network Architecture is fixed and provides a specific set of services to applications, Application Architecture is not*

- Network Application Architecture is designed by the devloper.
- Network App Architecture dictates how the app is structured over various end systems
- Two predominant Architectures
	- Peer-2-Peer
	- Client-Server

**Client-Server Architecture**
- Uses an Always-On host called *Server*
- Has a fixed IP Address
- Services requests from many other hosts called *clients*
- Server responds to a request from the client by sending them the requested object
- Do not directly communicate with each other (two browser do not directly communicate)
- Examples of Client-Server Architecture include FPT, Telnet, E-mail.
- A single server is unable to keep up with many client requests, *Data Centers* are used for scale

**P2P Architecture**
- Minimal to no reliance on dedicated servers
- Uses direct communication between pairs of intermittently connected hosts called *peers*
- *Peers* are desktops and laptops controlled by users
- Self-scalable (each peer generates workload by requesting files but also adds server capacity)
- cost effective
- Face security challenges, performance and reliability challenges due to high decentralized infra

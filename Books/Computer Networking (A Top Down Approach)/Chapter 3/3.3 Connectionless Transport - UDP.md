## Introduction
---
DNS is an example of an application-layer protocol
- Constructs a DNS query message
- passes the message to UDP
- Host UDP adds header fields to the message (without any handshakes)
- Passes the resulting segment to the network layer
- Network layer encapsulates the UDP segment into a datagram
- Datagram is sent to Name Server
- DNS application at the querying host waits for a reply to its query
- If no reply received, can try to resend the query, resend to another Name Server, or inform the application that it cant get a reply.

## Benefits of UDP over TCP
---


| Benefit                         | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Finer Application Level Control | As soon as an application processes passes data to UDP, it will package the data inside a UDP Segment and immediately pass the segment to the network layer.<br><br>TCP's congestion-control mechanism throttles the transport-layer TCP sender when one or more links between source and destination hosts become congested.<br><br>TCP will also continue to resend a segment until the receipt of the segment has been acknowledged by the destination regardless of how long reliable delivery takes.<br><br>Real-time apps require a minimum sending rate, don't want to overly delay segment transmission, and can tolerate some data loss. |
| No Connection Establishment     | TCP uses a three-way handshake, UDP just blasts away without any formal preliminary, no delay to establish a connection.<br><br>DNS uses UDP, using TCP would be much slower in establishing connections.<br><br>HTTP uses TCP but Chrome uses QUIC (Quick UDP Internet Connection) as an underlying transport protocol and implements reliability in an application-layer protocol on top of UDP.                                                                                                                                                                                                                                                |
| No Connection State             | TCP maintains connection state in end systems, causing receive and send buffers, congestion-control parameters, sequence and acknowledgement number parameters. This causes a lot of overhead.                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Small Packet Header Overhead    | TCP Segment has 20 bytes of header overhead in every segment.<br><br>UDP only has 8 bytes of overhead.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

## 3.3.1 UDP Segment Structure
---
*UDP header has only four fields, each consisting of two bytes.*

| Field                | Description                                                                                                                                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Source & Dest Port # | Port numbers allow the destination host to pass the application data to the correct process running on the destination end system (demultiplexing)                                                           |
| Length               | Specifies the number of bytes in the UDP segment (header plus data). <br><br>An explicit length value is needed since the size of the data field may differ from one UDP segment to the next.                |
| Checksum             | Used by the receiving host to check whether errors have been introduced into the segment.                                                                                                                    |
| Application Data     | Application date occupies the data field of the UDP segment.<br><br>For DNS, DNS data field contains either a query message or a response message<br>For Audio Streaming, audio samples fill the data field. |

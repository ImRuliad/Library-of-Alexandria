## ***3.5.1 The TCP Connection***
---
*TCP is said to be a connection-oriented transport because before one application can begin to send data to another, the two processes must first "handshake" with eachother*

- The TCP connection is not an end-to-end TDM or FDM circuit as in a circuit-switched network.
- Connection is a "logical" one, with the common state residing only in the TCPs in the two communicating end systems
- Since TCP only runs in the end systems, and not the intermediary network elements
- Intermediary network elements do not maintain the TCP connection
- Intermediary network elements are completely oblivious to TCP connection

TCP provides a full-duplex service

- If there is a TCP connection between Process A on one host and Process B on another host then application-layer data can flow in both directions between both processes
- TCP is always point-to-point between a single sender and single receiver
- Multicasting, the transfer of data from one sender to multiple receivers in a single send operation, is not possible with TCP

How are TCP connections established?

- Client application process informs the client transport layer that it wants to establish a connection
	- `clientSocket.connect((serverName, serverPort))`
	- serverName is the name of the server
	- serverPort identifies the process on the server
- TCP in the client establishes a TCP connection with TCP in the server
	- Client sends a special TCP segment
	- Server responds with a second special TCP segment
	- These two segments carry no payload
	- The third may carry a payload
	- These three segments are known as the *Three-Way Handshake*
- Once TCP is established, processes can send data to each other.
- Client process passes a stream of data through the socket.
	- Once the stream of data is out of the socket, it is now in the hands of TCP running in the client
- TCP directs this data to the connection's *Send Buffer*
	- This buffer is set aside during the *Three-Way Handshake*
- From time to time, TCP will grab chunks of data from the *Send Buffer* and pass to the network layer
- The maximum amount of data that can be grabbed and placed in a segment is limited by *MSS (Maximum Segment Size)*

How is MSS determined?

- MSS is typically set by determining the length of the largest link-layer frame that can be sent by the local sending host
	- This is known as the *MTU (Maximum Transmission Unit)*
- Sets the MSS to ensure that a TCP segment (When encapsulated in a IP datagram) plus TCP/IP header length (40 bytes) will fit into a single link-layer frame.
- Both ethernet and PPP have an MTU of 1500 bytes.
	- Thus, a typical value of MSS is 1460 bytes
- MSS is the maximum amount of application-layer data in the segment, not the maximum size of the TCP segment including headers.

## 3.5.2 TCP Segment Structure
---
*TCP segments consist of header fields and a data field*

- Data field contains a chunk of application data
- MSS limits the maximum size of a segment's data field
- When TCP sends a large file, it breaks the file into chunks of size MSS (except for last chunk)

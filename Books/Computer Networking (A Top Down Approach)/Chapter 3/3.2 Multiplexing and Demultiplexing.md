
Imagine you are running 4 different processes on the same system
- Two telnet processes
- One FTP process
- One HTTP process

When the transport layer in your computer receives data from the network layer, how does it route the received data to one of these four processes?
- A process can have one or more sockets
- Transport layer of the receiving host deliver data to a socket
- Each socket has a unique identifier
- Format of the identifier depends on whether it is a TCP or UDP socket.

How does a receiving host direct incoming transport-layer segments to the appropriate socket?
- Each segment has a set of special fields.
- Transport layer examines these fields to identify the receiving socket
- Transport layer then directs the segment to that socket


| Name           | Description                                                                                                                                                                                                                         |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Demultiplexing | The process of delivering data in a transport-layer segment to the correct socket.                                                                                                                                                  |
| Multiplexing   | The process of gathering data chunks at the source host from different sockets, encapsulating each data chunk with header info (used later in demultiplexing) to create segments,<br>and passing the segments to the network layer. |


The special fields in a segment are called
- Source Port Number Field
- Destination Port Number Field
- Each port number is 16-bits
- Ranging from 0 - 65535
- Ports from 0 - 1023 are called well-known ports and are restricted for well known use


#### ***Connectionless Multiplexing and Demultiplexing***
---
We can create a UDP socket using
```python
clientSocket = socket(AF_INET, SOCK_DGRAM)
```
- Transport layer automatically assigns a port number to the socket
- Assigned port number between 1024 - 65535
- Assigned port number is not being used by any other UDP port in the host

We can bind the socket to associate it with a specific port number
```python
clientSocket.bind(('', 19157))
```

So what actually happens in UDP multiplexing/demultiplexing?
Imagine a process in Host A (UDP Port 19157) wants to send a chunk of application data to a process in Host B (UDP Port 46428)
- Transport layer in Host A creates a segment that includes
	- Application Data
	- Source Port Number (19157)
	- Destination Port Number (46428)
	- Two other irrelevant values
- Transport layer passes the resulting segment to the network layer
- Network layer encapsulates segment in an IP datagram
- Makes a best-effort attempt to deliver the segment to the receiving host.
- Segment arrives at Host B
- Transport layer in Host B examines the destination port number in the segment (46428)
- Delivers the segment to its socket identified by port 46428

#### ***Connection-Oriented Multiplexing and Demultiplexing***
---
One difference between a TCP and UDP Socket: TCP uses a 4-tuple identification
Used when a TCP segment from the network arrives at a host and uses the four values to direct (de-multiplex) the segment to the socket.

TCP Client-server programming example
- TCP Server application has a "welcoming socket" that waits for a connection establishment request from TCP clients
	- Port number 12000
- TCP Client creates a socket and sends a connection establishment request segment with the following lines
- ```python
  clientSocket = socket (AF_INET, SOCK_STREAM)
  clientSocket.connect((serverName, 12000))
  ```
- A connection establishment request is nothing more than a TCP segment with destination port number 12000.
	- Locates the server process that is waiting to accept a connection on port number 12000
	- Server process then creates a new socket: `connectionSocket, addr = serverSocket.accept()`
- Transport layer notes the following for values in the connection-request segment
	- Source Port Number in the segment
	- IP address of the source host
	- Destination Port number in the segment
	- Its own IP address

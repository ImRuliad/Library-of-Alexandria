## 3.7.1 Classic TCP Congestion Control
---
*The approach taken by TCP is to have each sender limit the rate at which it sends traffic into its connection relative to perceived network congestion*

- If the TCP sender perceives that there is little congestion on the path between itself and destination then it will increase its send rate
- If the TCP sender perceives that there is congestion along the path then it will decrease its send rate

> [!Note] Three Questions Arise From the Above
> - How does a TCP sender limit the rate at which it sends traffic?
> - How does a TCP sender perceive that there is congestion on the path between itself and the destination?
> - What algorithm should the sender use to change its send rate from the perceived end-to-end congestion?

Each side of a TCP connection consists of
- A receive buffer
- A send buffer
- Several Variables (`LastByteRead`, `rwnd`, etc...)

The TCP congestion-control mechanism at the sender keeps track of an additional variable
- Congestion Window

The congestion window (`cwnd`) imposes a constraint on the rate at which TCP sender can send traffic into the network.
The amount of unacknowledged data a sender may NOT exceed is the minimum of `cwnd` and `rwnd`

$$
LastByteSent - LastByteAcked <= min(cwnd, rwnd)
$$
At the beginning of every `RTT` the constraint permits the sender to send `cwnd` bytes of data into the connection.
At the end of every `RTT` the sender receives acknowledgments for the data, therefore, the senders rate is roughly

$$
cwnd/RTT \ bytes \ per \ second
$$
By adjusting the value of `cwnd` the sender can adjust the rate at which it sends data into its connection.

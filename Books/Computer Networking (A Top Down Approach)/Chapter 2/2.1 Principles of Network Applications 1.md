*The core of network application development is writing programs that run on different end systems and communicate with each other over the network*

- This does not require you to write software that runs on network-core devices (routers & switches)
- Network-core devices do not function at the application layer but at the network layer and below.

## ***2.1.1 Network Application Architectures***
---
*Network Architecture is fixed and provides a specific set of services to applications, Application Architecture is not*
- Network Application Architecture is designed by the devloper.
- Network App Architecture dictates how the app is structured over various end systems
- Two predominant Architectures
	- Peer-2-Peer
	- Client-Server

**Client-Server Architecture**
*There is an always-on host, called the server, which services requests from many other hosts, called clients*
- Server must always have the same IP (Static IP)
- Server must always be kept on / alive

**Peer-2-Peer** Architecture
*Applications directly connect between pairs of intermittently connected hosts, called peers*
- Self-Scalable
- Each pair generates workload by requesting files
- Each pair also adds server capacity to the system by distributing files to other peers
- P2P Face security challenges, performance challenges, and reliability challenges.

#### ***2.1.2 Processes Communicating***
---
*Any message sent from one process to another must go through the underlying network.*

- A process sends messages into and receives messages from the network through a socket.
- A socket is the interface between the application layer and the transport layer within a host.
- This is also referred to as an Application Programming Interface (API) between the application and network
- The application developer has control of everything on the application-layer side.
- The application developer has little to no control of the transport layer side.
	- Can only choose the transport protocol
	- Maximum buffer and maximum segment sizes

 ***Addressing Processes***
*To send and receive data you must know where to send the data (IP Address) and what socket should recieve that data (Port Number)*

### ***2.1.3 Transport Services Available to Applications***
---
- Packets can get lost in a computer network
- Can have devastating effects if packets get lost between bank/customer, File transfer, remote host access, etc...
- Protocols can provide Reliable Data Transfer
- Reliable Data Transfer sends data into the socket.

***Throughput***
- Certain processes need a guaranteed throughput of r bits/sec
- If transport protocol cannot provide this throughput, the application will encode at a lower rate
- Applications that have throughput requirements are bandwidth-sensitive applications.
- Elastic Applications, on the other hand, can make use of as much or as little throughput available.
***Timing***
- Transport Layer can also provide timing guarantees.
- e.g. every bit that the sender pumps into the socket but arrive no more than 100 msec later.
- appealing to multiplayer games, Internet Telephony, etc...
- Lower delay is always preferable over high delay.






## ***2.2.1 Overview of HTTP***
---
- Defined in RFC 1945, 7230, and 7540
- Implemented in two programs: A Client Program and Server Program
- These programs execute on different systems and exchange HTTP messages
- HTTP defines the structure of these messages and how the client and server exchange the messages

**Web Pages**
- Consist of objects
- Objects are files, like HTML files, JPEG image, JS File, CSS File, etc....
- Most web pages consist of a base HTML file and several referenced objects
- If a web page contains an HTML file and 5 JPEG images, then the web page contains 6 objects.
- The HTML file references other objects in the page via their URLs.
- Web Browsers implement the client side of HTTP
- Web Servers implement the server side of HTTP
- Each URL has two components
	- The hostname of the server that houses the objects
	- The object's pathname

`http://www.someSchool.edu/someDepartment/picture.gif`

| Hostname                    | Object Path                   |
| --------------------------- | ----------------------------- |
| `http://www.someSchool.edu` | `/someDepartment/picture.gif` |

**HTTP Behavior**
- HTTP requests messages for the objects in the server
- Server receives the request and responds with messages that contain the objects
- HTTP Client initiates a TCP connection
- Browser (Client) and Server process access TCP through their sockets
- HTTP does not know anything about the client that requests objects, thus it is called a stateless protocol.

## ***2.2.2 Non-Persistent and Persistent Connections***
---
*Should each request/response pair be made in separate TCP connections, or should all requests/responses be sent over the same TCP connection?*

- Using separate TCP connections is a non-persistent connection
- Using the same TCP connection is a persistent connection
- HTTP uses persistent connection in its default mode
- HTTP servers and clients can be configured to use non-persistent connection
- HTTP/1.0 uses Non-Persistent Connections

#### **HTTP with Non-Persistent Connections**
*Assume a page consists of a base HTML file and 10 JPEG images and all 11 objects reside in the same server*
*Suppose that the URL for the base HTML file is `http://www.someSchool.edu/someDepartment/home.index`*

Here is what happens:
1. HTTP Client process initiates a TCP connection to the server on port 80.
2. HTTP Client sends an HTTP request message to the server via its socket. Request message includes the path name `/someDepartment/home.index`
3. HTTP Server process receives the request message via its socket, retrieves the object `/someDepartment/home.index` from its storage (RAM or disk), serializes/marshals it into an HTTP response message, and sends the response message to the client via its socket.
4. HTTP Server process tells TCP to close the TCP connection
5. HTTP Client receives the response message.
6. TCP Connection terminates
7. Messages indicates that the encapsulated object is an HTML file
8. Client extracts the file from the response message, examines the HTML file, and finds references to the 10 JPEG objects
9. First four steps are repeated for each of the referenced JPEG objects

> [!Danger] Problems with Non-Persistent Connection
> - Brand-new connections must be established and maintained for each requested object
> - Each of these connections must allocate TCP buffers
> - Each of these connections must keep TCP variables in both client and server
> - Significant burden on the Web server
> - Each object suffers a delivery delay of two RTTs (One RTT to establish the TCP connection and one RTT to request and receive an object)

#### **HTTP with Persistent Connections**
- Employed in HTTP/1.1
- Server leaves TCP connection open after sending a response
- Subsequent requests and responses between same client and server use the same connection (e.g. The base HTML file and the 10 images can be served over the same connection)
- Multiple web pages from the same server can be sent from the server to the same client over a single persistent TCP connection
- Request for objects can be made back-to-back without waiting for replies to pending requests (pipelining)
- HTTP Server closes the TCP connection when it isn't used for a certain time.

## ***2.2.3 HTTP Message Format***
---
*There are two types of HTTP messages: Request messages & Response messages*

#### **HTTP Request Message**
```
GET /somedir/page.html HTTP/1.1
Host: www.someschool.edu
Connection: close
User-agent: Mozilla/5.0
Accept-language: fr
```
- This HTTP request message has 5 lines
- HTTP request messages can have many more lines or as few as one line
- The first line is called the **Request Line**
- The subsequent lines are called the **Header Lines**

The **Request Line** has three fields: The method field, URL field, and HTTP version field

| Method Field | URL Field          | HTTP Version Field | Full Request Line                 |
| ------------ | ------------------ | ------------------ | --------------------------------- |
| GET          | /somedir/page.html | HTTP/1.1           | `GET /somedir/page.html HTTP/1.1` |

The **header lines**

| Header Line                | Description                                                                                                                                                                 | Notes                                                                        |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `Host: www.someschool.edu` | specifies the host on which the object resides                                                                                                                              | Host header line is required by Web proxy caches                             |
| `Connection: close`        | Browser is telling the server that it doesn't want to bother with persistent connections.<br>It wants the server to close the connection after sending the requested object |                                                                              |
| `User-agent: Mozilla/5.0`  | Specifies the browser type that is making the request to the server                                                                                                         | Server can send the same object to different versions / types of user agents |
| `Accept-language: fr`      | Specifies what version of the object to be sent to client                                                                                                                   | Content negotiation header                                                   |

#### **HTTP Response Message**
```
HTTP/1.1 200 OK
Connection: close
Date: Tue, 18 Aug 2015 15:44:04 GMT
Server: Apache/2.2.3 (CentOS)
Last-Modified: Tue, 18 Aug 2015, 15:11:03 GMT
Content-Length: 6821
Content-Type: text/html

(Data, Data, Data......)
..
..
..
```

The structure of the Response Message

| Response Line Type | Response Line Content                                                                                                                                                                                     |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 Status Line      | `HTTP/1.1 200 OK`                                                                                                                                                                                         |
| 6 Header Lines     | `Connection: close`<br>`Date: Tue, 18 Aug 2015 15:44:04 GMT`<br>`Server: Apache/2.2.3 (CentOS)`<br>`Last-Modified: Tue, 18 Aug 2015, 15:11:03 GMT`<br>`Content-Length: 6821`<br>`Content-Type: text/html` |
| Entity Body        | `(Data, Data, Data........)`                                                                                                                                                                              |

What each Response Line means

| Response Line                                   | Line Type   | Description |
| ----------------------------------------------- | ----------- | ----------- |
| `HTTP/1.1 200 OK`                               | Status Line |             |
| `Connection: close`                             | Header Line |             |
| `Date: Tue, 18 Aug 2015 15:44:04 GMT`           | Header Line |             |
| `Server: Apache/2.2.3 (CentOS)`                 | Header Line |             |
| `Last-Modified: Tue, 18 Aug 2015, 15:11:03 GMT` | Header Line |             |
| `Content-Length: 6821`                          | Header Line |             |
| `Content-Type: text/html`                       | Header Line |             |
| `(Data, Data, Data....)`                        | Body        |             |





## ***Compilers, Assemblers, and Linkers***
---
- A C program's building process involves four stages
	- Preprocessing
	- Compiler
	- Assembler
	- Linker
- At the end, there should be a single executable file

| #   | Name          | Description                                                                                                                                                                                                                                                                                             |
| --- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Preprocessing | Processes include-files, conditional compilation instructions and macros                                                                                                                                                                                                                                |
| 2   | Compilation   | Takes the output of the preprocessor and the source code and generates assembler source code                                                                                                                                                                                                            |
| 3   | Assembly      | Takes the assembly source code and produces an assembly listing with offsets. The assembler output is stored in an object file                                                                                                                                                                          |
| 4   | Linking       | Takes one or more object files or libraries as input and combines them to produce a single executable file. <br>Resolves references to external symbols, assigns final addresses to procedures/functions and variables.<br>Revises code and data to reflect new addresses (a process called relocation) |

For any given input file, its file extension determines what kind of compilation is done. Here are some examples

| File Extension                                                 | Description                                                                                                                 |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| file_name.c                                                    | C source code which must be preprocessed                                                                                    |
| file_name.i                                                    | C source code which should not be preprocessed                                                                              |
| file_name.ii                                                   | C++ source which should not be preprocessed                                                                                 |
| file_name.h                                                    | C header file (not to be compiled or linked)                                                                                |
| file_name.cc<br>file_name.cp<br>file_name.cpp<br>file_name.c++ | C++ source code which must be preprocessed.                                                                                 |
| file_name.s                                                    | Assembler code                                                                                                              |
| file_name.S                                                    | Assembler code which must be preprocessed                                                                                   |
| file_name.o                                                    | Object file by default, the object file name for a source file is made by replacing the extension .c, .i, .s etc... with .o |

## ***Object Files and Executables***
---
- After source code has been assembled it will produce an Object file
- Object file will be linked and Executable file will be produced
- Object files and executables come in several formats such as ELF (Executable and Linking Format) and COFF (Common Object-File Format)
- ELF is used for Linux
- COFF is used for Windows

| Object File Format | Description                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| a.out              | The `a.out` format is the original file format for Unix.  <br>It consists of three sections: `text`,`data`, and `bss`, which are for program code, initialized data, and uninitialized data, respectively.  <br>This format is so simple that it doesn't have any reserved place for debugging information.  <br>The only debugging format for `a.out` is stabs, which is encoded as a set of normal symbols with distinctive attributes. |
| ELF                | The ELF (Executable and Linking Format) format came with System V Release 4 (SVR4) Unix.  <br>ELF is similar to COFF in being organized into a number of sections, but it removes many of COFF's limitations.  <br>ELF used on most modern Unix systems, including GNU/Linux, Solaris and Irix. Also used on many embedded systems.                                                                                                       |
| COFF               | The COFF (Common Object File Format) format was introduced with System V Release 3 (SVR3) Unix. <br>COFF files may have multiple sections, each prefixed by a header. The number of sections is limited.  <br>The COFF specification includes support for debugging but the debugging information was limited.  <br>There is no file extension for this format.\|                                                                         |

- Object files have areas called sections
- Sections can hold executable code, data, dynamic linking information, debugging data, symbol tables, relocation information, comments, string tables, and notes
- Some sections are loaded into the process image and some provide info needed in the building of a process image while others are used only in linking object files

Here are examples of sections that are common to all executable formats

| Section            | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `.text`            | This section contains the executable instruction codes and is shared among every process running the same binary. <br>This section usually has READ and EXECUTE permissions only. <br>This section is the one most affected by optimization.                                                                                                                                                                                                                                                                                                                                                                                   |
| `.bss`             | BSS stands for ‘Block Started by Symbol’. It holds un-initialized global and static variables. <br>Since the BSS only holds variables that don't have any values yet, it doesn't actually need to store the image of these variables. <br>The size that BSS will require at runtime is recorded in the object file, but the BSS (unlike the data section) doesn't take up any actual space in the object file.                                                                                                                                                                                                                 |
| `.data`            | Contains the initialized global and static variables and their values. It is usually the largest part of the executable. It usually has READ/WRITE permissions.                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `.rdata`           | Also known as .rodata (read-only data) section. This contains constants and string literals.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `.reloc`           | Stores the information required for relocating the image while loading.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Symbol Table       | A symbol is basically a name and an address.  Symbol table holds information needed to locate and relocate a program’s symbolic definitions and references. <br>A symbol table index is a subscript into this array. Index 0 both designates the first entry in the table and serves as the undefined symbol index.  <br>The symbol table contains an array of symbol entries.                                                                                                                                                                                                                                                 |
| Relocation Records | Relocation is the process of connecting symbolic references with symbolic definitions. <br>For example, when a program calls a function, the associated call instruction must transfer control to the proper destination address at execution. <br>Re-locatable files must have relocation entries’ which are necessary because they contain information that describes how to modify their section contents, thus allowing executable and shared object files to hold the right information for a process's program image.  <br>Simply said relocation records are information used by the linker to adjust section contents. |
